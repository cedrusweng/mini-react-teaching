技术设计文档：Mini React 协调器

用零依赖教学项目说明协调器的数据结构、调用时序、运行流程与核心算法。

版本 v1.0状态：草稿创建时间 2026-11-25作者 codebuddy-wxs

1. 概述

1.1 背景与目标

  • 要解决的问题：真实 React 源码模块多、调用链长，初学者难以直观理解协调器如何把 Element 变成 Fiber，再提交为 DOM。
  • 预期效果：用零依赖教学项目说明协调器的数据结构、调度方式、遍历算法与提交流程。
  • 涉及终端：浏览器教学演示页面、Node.js 零依赖静态服务器。

1.2 范围与边界

本次做

  • 定义 Element / Fiber / FiberRoot / Hook / UpdateQueue 等数据结构
  • 描述 setState 到 DOM 变化的完整调用时序
  • 给出用例图、流程图、状态流转与算法伪代码
  • 与教学版代码目录建立映射

本次不做

  • Lane 优先级与时间切片
  • 完整 keyed diff、错误边界、Suspense、Context、Ref
  • 生产环境性能优化与兼容实现

1.3 术语定义

术语说明
Element对界面长什么样是不可变描述，带 $$typeof 标识
Fiber协调器工作单元，承载组件类型、props、状态、树关系与副作用
FiberRoot渲染根节点，持有宿主容器与当前 Fiber 树
workInProgress本轮正在构建的 Fiber 副本，与 current 构成双缓冲
EffectTag提交阶段要执行的副作用：插入、更新、删除
协调比较新旧 Element，决定 Fiber 复用、新建或删除
提交把协调结果同步转化为真实 DOM 操作

3. 数据结构

3.1 React Element

字段类型含义
$$typeofSymbolREACT_ELEMENT_TYPE，标识这是 React Element
typeString / Function / Symbol宿主标签名、函数组件或文本类型
keyString / null列表协调时识别同一节点
propsObject属性与 children；key/ref 不在其中

3.2 Fiber 节点

字段含义在算法中的作用
tag节点类型编号beginWork 按 tag 分派
type组件函数或宿主标签判断新旧节点能否复用
key列表标识与 type 共同决定复用
pendingProps本轮新 props渲染与协调输入
return / child / sibling父、子、兄弟指针构成 Fiber 树，供遍历与事件冒泡
stateNodeDOM 节点或 FiberRootcommit 阶段执行宿主操作
alternate双缓冲另一棵树节点workInProgress 复用
memoizedStateHook 链表头函数组件状态存储
effectTag副作用标记决定插入/更新/删除
deletions待删除子 Fibercommit 前统一收集

3.3 FiberRoot / Hook / UpdateQueue

对象字段含义
FiberRootcontainerInfo宿主容器 DOM 节点
FiberRootcurrent / finishedWork当前树与本轮完成树
HookmemoizedState当前状态值
Hookqueue / next更新队列与下一个 Hook
UpdateQueuepending / dispatch待处理 action 与 setState 函数

3.4 枚举定义

WorkTag

常量值
FunctionComponent0
HostRoot1
HostComponent2
HostText3

EffectTag

常量触发条件
PLACEMENT首次创建或 type/key 不匹配
UPDATEtype/key 相同
DELETION旧节点在新 children 中不存在

BR-002渲染阶段不操作 DOMbeginWork / completeWork只构建 Fiber 与实例
BR-003type 与 key 相同才复用reconcileChildren标记 UPDATE

8. 算法设计

8.1 批处理调度

rootsToSchedule.add(root)
if isScheduled == false:
    isScheduled = true
    scheduleCallback(flushScheduledRoots)

要点：Set 去重；Scheduler 用微任务异步触发 flushWork。

8.2 双缓冲创建

createWorkInProgress(current):
    wip = current.alternate
    if wip 为空:
        wip = 新建 Fiber(复制 tag/type/key/stateNode)
        current.alternate = wip
        wip.alternate = current
    否则:
        复用 wip，更新 return / pendingProps / stateNode

    复制 memoizedProps、memoizedState
    清空 child、sibling、effectTag、deletions
    return wip

8.3 子节点协调

reconcileChildren(wip, children):
    childElements = 拍平 children，过滤 null/undefined/boolean
    原始值包装为文本 Element
    oldFiber = wip.alternate?.child

    遍历 childElements：
        若 oldFiber 存在 且 type 相同 且 key 相同:
            newFiber = createWorkInProgress(oldFiber)
            newFiber.effectTag = UPDATE
        否则:
            newFiber = createFiberFromElement(element)
            newFiber.effectTag = PLACEMENT
            若 oldFiber 存在:
                oldFiber.effectTag = DELETION
                加入 wip.deletions

        串入 child / sibling 链
        oldFiber = oldFiber.sibling

    剩余 oldFiber 全部标记 DELETION

8.4 Hooks 状态更新

renderWithHooks(wip):
    dispatcher = wip.alternate === null ? OnMount : OnUpdate
    ReactCurrentDispatcher.current = dispatcher

mountState:
    创建 Hook { memoizedState, queue }
    queue.dispatch = dispatchSetState.bind(null, fiber, queue)

updateState:
    按 Hook 顺序复用
    执行 queue.pending 中所有 action
    清空 pending

dispatchSetState:
    queue.pending.push(action)
    scheduleUpdateOnFiber(root, fiber)

8.5 遍历与提交

performUnitOfWork(fiber):
    beginWork(fiber)
    if fiber.child 存在: return fiber.child
    向上回溯：
        completeWork(当前节点)
        if 有 sibling: return sibling
        当前节点 = return
    return null

commitRoot(root, finishedWork):
    收集 deletions
    先执行删除
    深度优先遍历：
        PLACEMENT → 插入 DOM
        UPDATE → 更新属性/文本
    root.current = finishedWork

8.6 复杂度

阶段复杂度说明
调度入队O(1)Set.add，同一 root 去重
协调O(n)n 为某层子节点数，按索引比较
render 遍历O(F)F 为 Fiber 总数
commitO(F)删除、插入、更新各遍历一次

9. 数据影响

本教学版不涉及数据库，仅描述内存状态变化。
数据对象操作业务含义影响范围
FiberRoot.current提交后替换当前生效的 Fiber 树下一次更新基线
workInProgress每轮创建/复用正在构建的 Fiber 树render 阶段
Hook.queue.pending追加/清空暂存用户更新动作updateState
DOM → Fiber 映射commit 写入支持事件反查 Fiber事件系统
真实 DOM增删更新页面最终呈现用户可见界面

10. 非功能需求

性能与规模

  • 教学版预期不超过数百个 Fiber
  • 微任务模拟异步批处理
  • 不实现时间切片与优先级抢占

兼容性与限制

  • 无外部依赖
  • 需支持 ES Module / Symbol / WeakMap / queueMicrotask
  • 列表 diff 为索引 + type/key，不是完整 keyed diff

12. 上线策略

本设计对应本地教学项目，不涉及线上灰度。

  • 灰度方案：无；通过教学版本文件分发。
  • 回滚方案：回退本需求目录与教学项目文件，无数据迁移。
  • 监控告警：无生产指标；验证方式为语法检查、冒烟脚本与动画页面人工走查。
